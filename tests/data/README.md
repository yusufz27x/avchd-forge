# Test data provenance

Two kinds of fixtures live here. **Real** fixtures are raw `ffprobe -print_format
json -show_format -show_streams` output captured from files generated by
`scripts/generate_test_fixtures.sh` (they also carry an `_fixture_note` field
explaining their origin). **Handcrafted** fixtures are written by hand because the
codec in question cannot be produced locally (ffmpeg has no DTS-HD MA, Blu-ray
TrueHD or PGS *encoder*), but their key names, index ordering and `disposition`
shape are copied from real output.

| File | Kind | Purpose |
| --- | --- | --- |
| `ffprobe/mkv_1080p_h264_ac3x2_srt.json` | real | happy path: 1080p24 H.264 High@4.1, AC-3 5.1 (eng), AC-3 2.0 (jpn), SubRip (eng) |
| `ffprobe/mkv_720p_h264_aac_srt.json` | real | 720p60 at the AVCHD frame-rate ceiling, AAC (tolerated, not AVCHD-legal), SubRip |
| `ffprobe/mkv_1080p_hevc.json` | real | HEVC source that validation must reject |
| `ffprobe/ts_1080p_h264_dts.json` | real | MPEG-TS container, plain DTS (passthrough path) |
| `ffprobe/mkv_1080p_dtshd_truehd_ac3core.json` | handcrafted | DTS-HD MA (→ `dca_core`), TrueHD without core (→ refuse), TrueHD with a separate AC-3 core stream (→ demux), E-AC-3 (→ refuse, cannot become AC-3 losslessly), SubRip |
| `ffprobe/mkv_1440x1080i_h264_level51.json` | handcrafted | rule coverage: illegal resolution, interlaced, level 5.1, high bitrate, oversized PGS, VobSub |
| `ffprobe/mkv_two_video_streams.json` | handcrafted | two video streams → hard error |
| `ffprobe/mkv_720p_lpcm_multi.json` | handcrafted | LPCM 96 kHz and 8-channel LPCM warnings, AAC warning, PGS at 720p |
| `ffprobe/ffprobe_empty.json` | handcrafted | degenerate response (no streams, no format) |
| `tsmuxer/detect_*.txt` | real | captured `tsMuxeR <file>` track-detection output (Track ID numbering, stream types, languages) |
| `tsmuxer/mux_success.txt` | real | full stdout of a successful `tsMuxeR <meta> <out>` AVCHD mux: `N% complete` lines, frame counter, `Mux successful complete` sentinel — the parsers in `progress.py` are asserted against it |
| `tools/*.txt` | real | captured `ffmpeg -encoders/-bsfs/-muxers/-version`, `ffprobe -version` and `tsMuxeR --version` output: the parsers in `tooling.py` are asserted against these |
| `tools/ffmpeg_progress_subtitle.txt` | real | `ffmpeg -progress pipe:1 -nostats` blocks from an SRT conversion: the `FfmpegProgressScanner` fixture |
| `meta/*.meta` | golden | expected tsMuxeR meta-file output; update deliberately together with `meta.py` |
| `bdmv/avchd_index.bdmv` | real | `index.bdmv` tsMuxeR 2.7.0 wrote for a real single-title AVCHD run: the golden file for `bdmv.build_index` and `bdmv.season_navigation([0])` |
| `bdmv/avchd_movieobject.bdmv` | real | the matching `MovieObject.bdmv` (episode + TopMenu + FirstPlay objects): the golden file for `bdmv.build_movie_objects` |

The two `bdmv/` files come from the same `e2e`-style mux run as the
`tsmuxer/mux_success.txt` capture. They pin the byte layout of the navigation
data the season support writes itself (`src/avchdforge/bdmv.py`); libbluray's
parsers (`index_parse.c`, `mobj_parse.c`, `hdmv_vm.c`) are the reference for
what each field means, tsMuxeR's own output is the reference for the bytes.
The tree they were captured from is single-title, i.e. exactly
`season_navigation([0])` — see `tests/test_bdmv.py` for the byte-for-byte
assertions, and libbluray-driven behaviour checks (disc insert / Go To Title)
under `@pytest.mark.e2e` in `tests/test_e2e.py`.

`meta/plan_*.meta` are rendered from a whole `JobPlan` (`tests/plan_jobs.py`) rather
than from a bare `MuxJob`, i.e. they are what the application really sends.

Regenerate the real fixtures with `scripts/generate_test_fixtures.sh` and review
the diff before committing: a changed fixture means the local ffmpeg version
changed its reporting, not that the app regressed.
